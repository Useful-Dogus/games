## 1. 소개

### 1.1 목적

본 문서는 dogus 팀이 개발 및 운영하는 웹 기반 게임 플랫폼 **Dogus Games**의 플랫폼 레벨 소프트웨어 요구사항을 정의한다. 단일 모노레포 구조로 허브 사이트와 여러 게임 앱을 함께 관리하며, 새로운 게임을 지속적으로 추가·배포할 수 있는 확장 가능한 플랫폼 구축을 목표로 한다.

> 게임별 요구사항은 `docs/games/<slug>.md`에 개별 관리한다.

### 1.2 범위

| 컴포넌트 | URL | 설명 |
| ----------- | ------------------------------------- | --------------------- |
| 허브 사이트 | `dogusgames.com` | 게임 목록 메인 사이트 |
| 게임 앱 | `dogusgames.com/<slug>` | 각 게임별 앱 |

### 1.3 정의 및 약어

| 용어 | 정의 |
| -------------------------- | ---------------------------------------------------------- |
| 모노레포 (Monorepo) | 하나의 Git 레포지토리에서 여러 앱과 패키지를 관리하는 구조 |
| 허브 사이트 (Hub) | 게임 목록과 소개를 제공하는 메인 사이트 |
| 게임 앱 (Game App) | 개별 게임을 독립적으로 실행하는 웹 애플리케이션 |
| 공유 패키지 (Package) | 여러 앱이 공통으로 사용하는 코드 묶음 |
| 플레이스홀더 (Placeholder) | 실제 게임 로직 없이 UI 껍데기만 구성된 초기 상태 |
| Turborepo | 모노레포 태스크 실행 및 캐싱 빌드 툴 |
| pnpm workspace | 패키지 간 의존성을 관리하는 패키지 매니저 기능 |

## 2. 시스템 개요

### 2.1 제품 관점

Dogus Games는 웹 브라우저에서 바로 플레이할 수 있는 캐주얼 게임 플랫폼이다. 별도의 앱 설치 없이 URL 접근만으로 게임을 즐길 수 있으며, 허브 사이트(dogusgames.com)를 통해 게임 목록을 탐색하고 각 서브패스로 이동할 수 있다.

### 2.2 이해관계자

| 이해관계자 | 역할 | 주요 관심사 |
| ---------------------- | ------------------------ | ------------------------------------------- |
| dogus 팀 (개발자) | 플랫폼 및 게임 개발·운영 | 개발 생산성, 코드 재사용, 배포 자동화 |
| 최종 사용자 (플레이어) | 게임 플레이 | 빠른 로딩, 쾌적한 UX, 안정성 |
| 게임 디자이너 | 게임 컨텐츠 기획 | 게임 앱 추가 용이성, 플레이스홀더 구조 파악 |

### 2.3 제품 기능 요약

**허브 사이트 (`apps/web`)**

- 게임 카드 목록 렌더링 (썸네일, 제목, 설명, 장르 태그)
- 게임 앱 서브패스로의 네비게이션
- 신규 게임 추가 시 config 수정만으로 목록 자동 반영

**게임 앱 (`apps/<slug>`)**

- 게임별 스펙에 따른 단계별 구현(플레이스홀더 또는 플레이 가능 버전)
- 게임 이름 및 핵심 플레이 정보 제공
- 필요 시 허브 진입 링크를 포함하되, 게임 단독 UX를 우선할 수 있음

### 2.4 사용자 특성

- 별도 로그인 없이 게임에 바로 접근
- 모바일 및 데스크탑 브라우저 모두 사용
- 짧은 세션(5~15분)의 캐주얼 플레이 패턴

## 3. 기능 요구사항

우선순위 기준: **Must** (필수) / **Should** (권장) / **Could** (선택)

### 3.1 허브 사이트 (`apps/web`)

#### 3.1.1 게임 목록 페이지

| ID | 우선순위 | 요구사항 |
| ------- | -------- | ------------------------------------------------------------------------------------------------ |
| WEB-001 | Must | 게임 카드 목록을 그리드 형태로 렌더링한다. |
| WEB-002 | Must | 각 게임 카드는 썸네일 이미지, 게임 제목, 한 줄 설명, 장르 태그를 표시한다. |
| WEB-003 | Must | 게임 카드 클릭 시 `live` + 배포 URL 설정 게임은 외부 게임 URL로 이동하고, 그 외에는 해당 서브패스 안내 페이지(예: `/patisserie-drop`)를 표시한다. |
| WEB-004 | Must | 게임 메타데이터(제목, 설명, slug, 썸네일 경로)는 중앙 config 파일(`games.config.ts`)로 관리한다. |
| WEB-005 | Should | 신규 게임 추가 시 config 파일만 수정하면 목록에 자동 반영된다. |
| WEB-006 | Should | 게임이 없거나 준비 중인 경우 `Coming Soon` 배지를 카드에 표시한다. |
| WEB-007 | Could | 장르 태그 필터링으로 게임 목록을 좁힐 수 있다. |

#### 3.1.2 헤더 및 공통 레이아웃

| ID | 우선순위 | 요구사항 |
| ------- | -------- | --------------------------------------------------------------- |
| WEB-010 | Must | 헤더에 Dogus Games 로고(또는 텍스트)와 홈(`/`) 링크를 표시한다. |
| WEB-011 | Must | 푸터에 팀명(dogus)과 저작권 표시를 포함한다. |
| WEB-012 | Should | 페이지 `<title>`, OG 태그, favicon을 설정한다. |

### 3.2 게임 앱 — 공통 요구사항

게임 앱은 공통 기술 제약을 공유하되, UI/정보구조는 게임별 스펙(Phase)에 따라 달라질 수 있다.

| ID | 우선순위 | 요구사항 |
| -------- | -------- | -------------------------------------------------------------------------- |
| GAME-001 | Must | 각 게임 앱은 게임 이름과 핵심 플레이 정보(HUD 또는 동등 수준)를 표시한다. |
| GAME-002 | Should | 허브 복귀 링크는 게임별 UX 의도에 따라 포함 여부를 결정한다. |
| GAME-003 | Must | 게임 앱의 URL slug는 레포 디렉토리명과 동일하게 유지한다. |
| GAME-004 | Should | 미출시 단계에서는 `게임 준비 중` 또는 `Coming Soon` 안내를 표시한다. |
| GAME-005 | Could | 게임 앱은 독립적인 favicon과 OG 이미지를 갖는다. |

> 게임별 고유 요구사항은 `docs/games/<slug>.md`를 참조한다.

## 4. 비기능 요구사항

### 4.1 성능

| ID | 요구사항 |
| -------- | ---------------------------------------------------------------------- |
| PERF-001 | 허브 사이트의 초기 로딩(LCP)은 3G 환경 기준 3초 이내여야 한다. |
| PERF-002 | 게임 앱 플레이스홀더 페이지는 2초 이내에 완전히 렌더링되어야 한다. |
| PERF-003 | 이미지 에셋은 최적화(WebP, lazy loading)하여 불필요한 대역폭을 줄인다. |

### 4.2 가용성 및 신뢰성

| ID | 요구사항 |
| --------- | ----------------------------------------------------------- |
| AVAIL-001 | 서비스 가용성 목표는 월간 99.5% 이상이다. |
| AVAIL-002 | 빌드 실패 시 이전 배포 버전으로 즉시 롤백할 수 있어야 한다. |

### 4.3 유지보수성

| ID | 요구사항 |
| -------- | ------------------------------------------------------------------------------------------------- |
| MAIN-001 | 신규 게임 앱 추가 시 기존 코드 변경 없이 config 파일과 새 앱 디렉토리 추가만으로 완성되어야 한다. |
| MAIN-002 | 공유 패키지(`packages/*`) 변경 시 영향받는 앱만 자동으로 재빌드된다(Turborepo 캐싱 활용). |
| MAIN-003 | 모든 코드는 TypeScript로 작성하며, strict 모드를 적용한다. |
| MAIN-004 | ESLint + Prettier 규칙을 `packages/config`에서 일괄 관리한다. |

### 4.4 접근성 및 호환성

| ID | 요구사항 |
| ------- | -------------------------------------------------------------------------- |
| ACC-001 | 허브 사이트는 Lighthouse 접근성 점수 90점 이상을 목표로 한다. |
| ACC-002 | 지원 브라우저: Chrome, Safari, Firefox 최신 2개 버전 이상. |
| ACC-003 | 허브 사이트는 모바일(375px) ~ 데스크탑(1440px) 반응형 레이아웃을 지원한다. |

## 5. 시스템 아키텍처

### 5.1 레포 구조

```
games/                        # 모노레포 루트
├── apps/
│   ├── web/                  # 허브 사이트 (dogusgames.com)
│   └── <slug>/               # 게임 앱 (slug별 독립 앱)
│
├── packages/
│   ├── ui/                   # 공통 UI 컴포넌트
│   ├── game-core/            # 공통 게임 유틸 (향후 활용)
│   └── config/               # tsconfig, eslint, prettier 공통 설정
│
├── docs/                     # 레퍼런스 문서
│   ├── platform.md           # 이 문서
│   └── games/                # 게임별 요구사항
│
├── .agent/                   # 에이전트 협업 Single Source of Truth
├── turbo.json
├── pnpm-workspace.yaml
└── package.json
```

### 5.2 기술 스택

| 레이어 | 기술 선택 | 비고 |
| -------------- | -------------------------- | ------------------------- |
| 모노레포 | pnpm workspace + Turborepo | 빌드 캐싱, 병렬 실행 |
| 허브 사이트 | Next.js 15 (App Router) | SSG/SSR, 파일 기반 라우팅 |
| 게임 앱 (초기) | Next.js 또는 Vite + React | 게임 특성에 따라 선택 |
| 공통 UI | React + Tailwind CSS | packages/ui |
| 언어 | TypeScript (strict) | 전 앱 통일 |
| 배포 | Vercel | 앱별 독립 프로젝트 |

### 5.3 배포 전략

- 각 게임 앱은 독립된 Vercel 프로젝트로 배포한다.
- 허브(`apps/web`)는 게임 카탈로그/진입점 역할을 담당한다.
- 게임 상태가 `live`이고 배포 URL 환경변수가 설정된 경우 허브 카드에서 외부 게임 URL로 직접 이동한다.
- 배포 URL이 없는 slug는 허브 내부 안내 페이지(Coming Soon)로 처리한다.

### 5.4 게임 메타데이터 구조

```ts
// apps/web/config/games.config.ts
export interface GameMeta {
  slug: string;
  title: string;
  description: string;
  genre: string[];
  thumbnail: string;
  status: 'live' | 'coming-soon';
  deploymentEnvKey?: string; // 허브가 참조할 배포 URL 환경변수 키
}
```

## 6. 제약 사항 및 가정

### 6.1 제약 사항

- 초기 단계에서는 **백엔드 API, 사용자 인증, 점수 저장 기능을 포함하지 않는다.**
- 게임 앱은 초기에는 플레이스홀더로 시작할 수 있으며, 승인된 스펙/플랜이 있으면 Phaser/Pixi.js 등 엔진 도입이 가능하다.
- 배포는 Vercel 무료 플랜 기준으로 설계하며, 트래픽 급증 시 플랜 업그레이드를 고려한다.

### 6.2 가정

- 도메인 `dogusgames.com`은 팀이 이미 확보하였거나 확보 예정이다.
- 개발 환경은 Node.js 20 LTS 이상, pnpm 9 이상을 기준으로 한다.
- 게임 썸네일 이미지는 각 게임 개발 시 별도로 제작하여 추가한다. 초기 단계에서는 placeholder 이미지를 사용한다.
- 새로운 게임 앱 추가 시, `docs/games/<slug>.md`를 생성하여 해당 게임의 요구사항을 명세한다.
