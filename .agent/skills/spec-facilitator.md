# Skill: Spec Facilitator

Purpose:
- Converge ambiguous requirements into a clear, agreed spec by reducing assumptions.

Trigger:

- Requirements are vague.
- Agreement is needed before implementation.
- User requests "organize before coding."

Procedure:

1. Summarize current understanding in 3–5 sentences.
2. Build a list of missing-information questions.
3. For each question, provide options with a recommended choice.
4. Incorporate answers and draft a spec using `SPEC_TEMPLATE.md`.
5. Advance only after the approval checklist passes.

Question template:

- Problem definition: What is the core problem being solved?
- User / scenario: Who uses it and in what flow?
- Success criteria: How will completion be measured?
- Constraints: What are the technical, schedule, or policy constraints?
- Out of scope: What is explicitly excluded from this iteration?

Completion criteria:

- All acceptance criteria are written as testable sentences.
- Speculative expressions ("probably", "usually", "reasonably") have been removed.
