# 모노레포 부트스트랩 및 허브/게임 플레이스홀더 1차 구축 스펙

## 1. 문제 / 목표

- 문제:
  - 현재 레포지토리는 플랫폼/게임 요구사항 문서 중심 상태이며, 실제로 실행 가능한 모노레포 런타임 구조가 없다.
  - 이로 인해 신규 게임 추가 절차를 코드 단위로 검증할 수 없고, 배포-검증까지 포함한 운영 경로를 확인할 수 없다.
- 목표:
  - 신규 게임 추가의 기준 경로(이슈 → 개발 → PR → 병합 → 배포 → 검증)를 실행 가능한 형태로 확립한다.
  - 허브 앱과 초기 3개 게임 앱(플레이스홀더)이 동일 기준으로 동작하도록 최소 구현을 완료한다.
  - `main` 기준 Vercel 배포와 프로덕션 스모크 테스트 기록까지 첫 이슈 범위에서 완료한다.
- 범위 제외 (Out of Scope):
  - 실제 게임 로직 구현
  - 게임 엔진(Phaser, Pixi.js 등) 도입
  - 사용자 인증, 백엔드 API, 점수 저장
  - 고급 UI 시스템 도입(Tailwind 확장/디자인 시스템 고도화)

## 2. 사용자 시나리오

- 주요 사용자:
  - 플랫폼 개발자/리뷰어(개발 및 운영 담당)
  - 최종 사용자(플레이어)
- 핵심 사용자 흐름:
  1. 개발자는 모노레포를 설치하고 빌드하여 허브/게임 앱의 기본 동작을 확인한다.
  2. 플레이어는 허브에서 게임 목록을 보고 각 게임 슬러그 경로로 이동한다.
  3. 각 게임 앱에서 플레이스홀더 페이지를 확인하고 허브로 돌아갈 수 있다.
  4. 병합 후 프로덕션 환경에서 동일 경로를 스모크 테스트하고 결과를 이슈에 기록한다.
- 예외/실패 시나리오:
  - 전체 빌드 실패 시 병합하지 않고 실패 원인 및 재시도 계획을 이슈/PR에 기록한다.
  - 배포 또는 프로덕션 스모크 테스트 실패 시 이슈를 종료하지 않고 후속 조치 항목을 남긴다.

## 3. 수용 기준 (Acceptance Criteria)

1. 루트에서 `pnpm install`이 성공하고 의존성 설치 오류가 발생하지 않는다.
2. 루트에서 `pnpm turbo build`가 성공하고, 허브/게임 앱 관련 태스크 그래프 오류가 발생하지 않는다.
3. 허브 앱에서 초기 3개 게임(`patisserie-drop`, `sadari`, `santa-endless-runner`) 목록이 표시된다.
4. 각 게임의 슬러그 경로로 접근 시 플레이스홀더 페이지가 렌더링된다.
5. 허브 앱 설정에 3개 게임 슬러그 경로(`/patisserie-drop`, `/sadari`, `/santa-endless-runner`)를 각 게임 서비스 주소로 연결하는 규칙이 정의된다.
6. 루트에서 한 번의 명령(`pnpm dev:all`)으로 허브와 3개 게임 앱을 동시에 실행할 수 있다.
7. 각 게임 앱의 "허브로 돌아가기" 링크는 개발 환경 기본값으로 로컬 허브 URL(`http://127.0.0.1:3000`)을 사용하고, 환경변수로 재정의할 수 있다.
8. `main` 병합 후 운영 URL에서 허브 홈과 3개 게임 경로 접속 확인 결과(성공/실패, 시각, 링크)가 이슈 코멘트로 기록된다.

## 4. 비기능 요구사항

- 성능:
  - 플레이스홀더 수준 기준에서 허브/게임 초기 페이지는 사용자 체감상 즉시 렌더링되어야 하며, 명백한 로딩 지연(수 초 단위 blank screen)이 없어야 한다.
- 보안:
  - 이번 범위에서 인증/개인정보 처리는 다루지 않으며, 외부 입력 처리 기능을 새로 도입하지 않는다.
- 접근성:
  - 허브 및 플레이스홀더 페이지는 키보드 포커스 가능한 링크/버튼 구조를 유지한다.
  - 기본 시맨틱(heading, link, main 영역)을 유지한다.
- 관측 가능성 (로그/메트릭):
  - 빌드/스모크 테스트 실행 결과를 PR 또는 연결 이슈에 텍스트 로그로 남긴다.

## 5. 제약 / 의존성

- 기술 제약:
  - 모든 앱은 Next.js로 통일한다.
  - 스타일링은 최소 CSS만 사용한다.
  - 패키지 매니저는 pnpm만 사용한다.
  - 모노레포 태스크 실행은 Turborepo 기준으로 구성한다.
  - 로컬 개발 URL은 하드코딩 대신 환경변수 오버라이드가 가능해야 한다.
- 외부 의존성:
  - GitHub(이슈/PR), Vercel(배포/프로덕션 URL)
- 일정 제약:
  - 첫 PR에서는 모노레포 기반 확보와 플레이스홀더 동작 검증까지 완료하고, 고급 기능은 후속 이슈로 분리한다.
