# 모노레포 부트스트랩 및 허브/게임 플레이스홀더 1차 구축 플랜

## 1. 기술 방향

- 스택:
  - 모노레포: pnpm workspace + Turborepo
  - 앱 프레임워크: Next.js (허브 + 게임 앱 통일)
  - 언어: TypeScript (strict)
  - 스타일링: 최소 CSS (바닐라 CSS)
- 아키텍처:
  - `apps/web`: 허브 사이트(게임 목록, 라우팅 진입점)
  - `apps/<slug>`: 게임별 독립 플레이스홀더 앱 3종
  - `packages/ui`, `packages/game-core`, `packages/config`: 공유 레이어의 최소 스캐폴드만 선구축
  - 허브의 rewrite 규칙으로 `/slug` 경로를 각 게임 서비스 주소로 연결
  - 개발환경에서는 허브 rewrite 기본값을 localhost 포트(3001~3003)로 두고, 배포환경에서는 Vercel URL을 기본값으로 사용
- 설계 원칙:
  - 첫 PR은 "동작 가능한 최소 구조"에 집중하고 고급 기능은 후속 이슈로 분리
  - 신규 게임 추가 경로를 재사용 가능하게 만드는 구조 우선
  - `.agent` 문서와 구현 상태를 동기화하여 추적 가능성 확보
  - URL/링크 값은 환경변수로 덮어쓸 수 있도록 설계해 로컬/운영 전환 비용을 최소화

## 2. 시스템 영향도

- 변경 대상:
  - 루트: `package.json`, `pnpm-workspace.yaml`, `turbo.json`
  - 앱: `apps/web`, `apps/patisserie-drop`, `apps/sadari`, `apps/santa-endless-runner`
  - 패키지: `packages/ui`, `packages/game-core`, `packages/config`
  - 문서: `.agent/project/games-registry.md`, `docs/games/*.md`(정합성 확인), `.agent/specs/*`
- 통합 지점:
  - 허브 게임 메타데이터(`apps/web/config/games.config.ts`)
  - 허브 rewrite 설정(`apps/web/next.config.mjs`)
  - 환경변수 예시 파일(`.env.example`)과 앱별 링크 fallback 규칙
  - Turborepo 태스크 그래프(`turbo.json`)와 workspace 범위(`pnpm-workspace.yaml`)
- 마이그레이션 필요 여부:
  - 없음 (기존 실행 코드가 없는 초기 단계)

## 3. 대안 비교

- 옵션 A: 목표 구조(허브 + 3개 게임 + 공유 패키지 스캐폴드)를 첫 PR에서 일괄 구축
  - 장점: 문서상의 목표 구조와 코드 구조를 즉시 일치시킬 수 있음
  - 단점: 첫 PR 변경 범위가 상대적으로 큼
- 옵션 B: 허브(`apps/web`)만 먼저 구축하고 게임 앱/패키지는 후속 PR로 분할
  - 장점: PR 크기를 더 작게 가져갈 수 있음
  - 단점: "게임 추가 경로 검증"이 지연되어 첫 이슈 목표와 불일치
- 결정:
  - 옵션 A 채택
- 결정 근거:
  - 본 이슈 목표가 "게임 추가 가능한 모노레포 기준 경로 확립 + 배포 검증"이므로, 최소 3개 게임 플레이스홀더까지 포함해야 목표와 수용 기준을 한 번에 검증할 수 있다.

## 4. 리스크 및 대응

- 리스크:
  - Turborepo 태스크 정의 누락으로 전체 빌드 실패
  - 앱 간 설정 불일치(Next.js/TypeScript 버전, 스크립트 명칭)로 개발 경험 저하
  - rewrite 설정과 실제 배포 URL 불일치로 슬러그 접근 실패
- 대응 전략:
  - 초기 스캐폴드에서 스크립트/설정을 공통 패턴으로 통일
  - 루트 `dev:all` 스크립트로 허브/게임 앱 동시 실행 경로를 표준화
  - 허브/게임 URL은 환경변수 오버라이드를 우선 지원하고 로컬 기본값을 제공
  - `pnpm turbo build`를 병합 전 필수 검증으로 운영
  - 배포 후 허브 홈 + 3개 슬러그 스모크 체크를 이슈에 기록
- 롤백 전략:
  - 병합 후 치명적 문제 발생 시 직전 안정 커밋으로 롤백 배포
  - 문제 원인 분리 후 후속 PR로 재적용

## 5. 품질 / 운영 기준

- 테스트 전략:
  - 정적 검증: `pnpm install`, `pnpm turbo build`
  - 기능 검증(로컬/프리뷰): `pnpm dev:all` 실행 후 허브 목록 렌더링, 3개 슬러그 플레이스홀더 접근, "허브로 돌아가기" 링크 동작 확인
  - 운영 검증(프로덕션): 허브 홈 + 3개 슬러그 접속 결과를 이슈 코멘트로 기록
- 성능 기준:
  - 플레이스홀더 단계에서 허브/게임 첫 화면 진입 시 명백한 빈 화면 지연(수 초 단위)이 없어야 함
  - 불필요한 대용량 에셋 도입 금지
- 보안 기준:
  - 인증/개인정보 처리 없음
  - 외부 입력 기반 기능 미도입
  - 알려진 고위험 의존성 추가 금지(초기 스캐폴드 수준)
- 모니터링/알림:
  - 본 단계에서는 외부 모니터링 도구를 도입하지 않음
  - 최소 운영 로그는 PR 본문/이슈 코멘트로 대체
