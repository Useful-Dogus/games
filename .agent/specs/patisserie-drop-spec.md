## 1. Problem / Goal

- Problem:
  - 현재 `apps/patisserie-drop`는 플레이 가능한 게임 루프가 없고, 2단계에서 아트/사운드/연출을 올릴 확장 지점도 정의되어 있지 않다.
- Goal:
  - PRD v1.3의 핵심 플레이 규칙을 구현하여 실제 플레이 가능한 MVP를 제공한다.
  - 2단계에서 디자인/연출을 로직 수정 최소화로 추가할 수 있도록 교체 지점을 설계한다.
- Out of Scope (Phase 1):
  - 최종 아트 에셋 반영
  - 사운드/BGM 적용
  - 고급 VFX/애니메이션 폴리시 반영
  - 홈/이어하기/설정/기록/연습모드 등 메타 기능
  - 오버플로 경고 게이지/경고 인디케이터

---

## 2. User Scenarios

- Primary user:
  - 로그인 없이 짧은 시간(5~15분) 플레이하며 합성 퍼즐의 핵심 재미를 검증하려는 플레이어
- Core user flow:
  1. 사용자가 `apps/patisserie-drop`에 접속한다.
  2. 인게임 화면에서 즉시 플레이를 시작한다.
  3. 좌우로 위치를 정하고 탭/클릭으로 오브젝트를 드랍한다.
  4. 물리 안착 및 합성/연쇄 합성을 통해 점수를 획득한다.
  5. 상단 기준선 침범을 피하며 플레이를 지속한다.
  6. 기준선 침범 상태가 일정 시간 지속되면 게임오버 화면에서 점수를 확인하고 즉시 재시작한다.
- Exception / failure scenarios:
  - 런타임 에러가 발생하면 플레이 진행이 중단되므로, 1단계 완료 조건에서 치명적 에러 0건을 요구한다.
  - 모바일/데스크탑 화면에서 HUD 또는 입력 영역이 깨지면 조작 불가가 되므로 반응형 스케일 보장을 요구한다.

## 3. Functional Requirements (Phase 1 Scope)

1. 게임 루프
- 위치 결정(좌우 드래그) → 손을 떼면 드랍(release-to-drop) → 물리 안착 → 합성 판정 → 점수 반영의 반복 루프를 구현한다.

2. 물리/합성
- 엔진: Phaser 3 + Matter.js
- 동일 레벨 오브젝트 2개 접촉 시 상위 레벨 1개 생성
- 합성 결과물 생성 위치: 질량 중심
- 연쇄 합성 허용
- Lv11 합성 시 추가 진화 없이 점수만 지급

3. 드랍 시스템
- HUD의 `Next`에서 다음 2개 드랍 레벨을 표시한다.
- 플레이 필드 상단 프리뷰는 실제 드랍 가능한 상태에서만 표시한다.
- 점수 구간별 드랍 레벨 테이블 반영:
  - 0~199: Lv1~3
  - 200~799: Lv1~4
  - 800~2499: Lv1~5
  - 2500+: Lv1~6

4. 점수
- 합성 기본 점수, 고레벨 보너스 규칙을 PRD v1.3 기준으로 적용
- 콤보 시스템은 MVP 범위에서 제외한다.

5. 게임오버
- 상단 기준선 침범을 게임오버 조건으로 사용한다.
- 침범 상태가 `OVERFLOW_GAMEOVER_ACTIVATE_MS` 이상 지속되면 게임오버로 전환한다.
- 일시적 튐(짧은 침범)은 즉시 게임오버로 처리하지 않는다.

6. 최소 UI
- 인게임 HUD: 현재 점수, 다음 드랍 레벨
- 게임오버 UI: 최종 점수, 다시하기(즉시 리셋)

7. 2단계 확장성 요구
- 아트/사운드/연출 교체를 위한 지점을 로직과 분리한다.
- 최소 분리 단위:
  - 오브젝트 정의(레벨별 반지름/식별자/표시 메타)
  - 이벤트 훅(드랍/합성/게임오버)
  - 렌더 표현 레이어(임시 비주얼)와 게임 규칙 레이어 분리

---

## 4. Acceptance Criteria

1. PRD v1.3 기준 핵심 루프(위치 결정→드랍→물리 안착→합성→점수 반영)가 런타임 에러 없이 동작한다.
2. 드랍 등급, 고레벨 보너스, 기준선 침범 기반 게임오버 규칙이 명세대로 적용된다.
3. 480x854 내부 좌표계와 모바일/데스크탑 스케일링이 보장된다.
4. 아트/사운드/연출 치환 지점이 코드상 분리되어 2단계에서 로직 수정 없이 리소스 교체가 가능하다.
5. 최소 수동 테스트 시나리오(시작/플레이/게임오버/재시작)가 문서화된다.

## 5. Non-Functional Requirements

- Performance:
  - 1단계 기준, 일반 모바일/데스크탑 환경에서 핵심 조작이 끊기지 않아야 한다.
- Security:
  - 서버 통신 없이 클라이언트 상태만 사용하며, 외부 입력 기반 HTML 삽입을 금지한다.
- Accessibility:
  - 핵심 버튼 요소는 포커스 가능하고 텍스트 대비를 유지한다.
- Observability:
  - 개발자 콘솔 기준 치명적 에러 0건

## 6. Constraints / Dependencies

- Technical constraints:
  - `pnpm` 워크스페이스 규칙 준수
  - TypeScript strict 유지
  - 게임 엔진: Phaser 3 + Matter.js (PRD 명시)
  - 내부 좌표계 캔버스: 480x854 고정
- External dependencies:
  - 없음 (Phase 1에서 신규 외부 서비스 비의존)
- Non-goals:
  - 시각 완성도/브랜딩 완성은 Phase 2에서 처리
